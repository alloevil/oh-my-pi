## Failure evidence

The doctor `error-turns` rule warned on essentially every real session:
pressing ESC aborts the in-flight turn (`stopReason: "aborted"`, errorMessage
like "Interrupted by user"), and the rule counted each such turn as a failed
assistant turn. Deliberate user interruptions drowned out the genuine
degradation signal the rule exists for.

## Root cause

`evaluateErrorTurns` treated any non-null `errorMessage` or any stop reason
outside `{stop, toolUse}` as an error turn. `"aborted"` is in that set, but a
user abort is deliberate action, not degradation — the rule conflated the two.

## Targeted fix

Skip `stopReason === "aborted"` turns in `evaluateErrorTurns`; provider errors
(`error` stop reason / recorded `errorMessage`) and output-budget truncation
(`length`) still count. Test updated: user-aborted turns produce no
`error-turns` finding.

## Prediction

- User-abort turns excluded: `error-turns` findings on the reference session
  sweep drop (aborted-only sessions stop warning), and every remaining finding
  is a real provider-side failure.
- Real provider errors remain: an assistant turn with `stopReason: "error"` or
  a recorded `errorMessage` still yields an `error-turns` finding.
