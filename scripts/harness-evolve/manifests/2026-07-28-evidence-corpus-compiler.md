## Failure evidence

The four per-session health data sources exist but are only readable one
session and one lens at a time: `omp doctor` prints findings OR `--stages` OR
`--outbound` for a single session, and stats' `health_signals` rows are only
reachable programmatically. Reviewing harness health across recent sessions
means running `omp doctor` N×3 times and manually cross-referencing — in
practice nobody does, so degradation evidence (e.g. the provider stream stalls
surfaced by 2026-07-28-error-turns-aborted-calibration) is found by accident,
not by review.

## Root cause

No compilation layer. Each health source (doctor rules, stage timings,
outbound summaries, health signals) was built with its own single-session
renderer and there is no consumer that joins them across sessions into one
human-readable evidence document with source citations.

## Targeted fix

Pure compiler `compileEvidenceReport(inputs, options) -> string` in
`src/health/evidence.ts` over per-session bundles (doctor findings, stage
rows, outbound summaries, health-signal rows, each with source entry
indexes), emitting a three-layer markdown report: L1 cross-session overview
(finding counts by rule, per-session stage-p95 ranges, per-model signal
aggregates, honest `insufficient baseline` placeholder when data spans
< 7 days or health signals are empty), L2 deep-dives only for sessions with
≥1 warn finding or a stage p95 ≥ 2× the batch median (findings + outlier
turns + outbound diffs, chronologically interleaved, every claim ending in a
`[session:entryIndex]` ref), L3 appendix mapping refs to file paths. New
standalone CLI subcommand `omp evidence [--sessions N] [--out FILE] [--json]`
following the doctor-cli pattern (most-recent-N session resolution for cwd,
stats.db read-only and tolerated when missing). Read-only observability: no
new telemetry, no model calls, no prompt or tool-path changes, no canary
changes.
