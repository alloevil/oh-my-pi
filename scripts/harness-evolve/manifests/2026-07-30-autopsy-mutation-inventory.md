## Failure evidence

Incident #1 (session `019fac75`, the Mail-organizing task) moved real user
email via 120 synthesized ego-browser CDP clicks and repeated osascript
`move`/`make new` calls against Mail.app. Nothing in the transcript tooling
inventories what was mutated *outside the repository*: the autopsy reports
errors, command churn, ending, and asks — all mechanical/behavioral axes —
but if a message had been mis-filed by one of those 120 blind clicks there is
no audit trail to even start from. Recovering "what did the agent touch in
the user's world" today requires the same ad-hoc jq archaeology the autopsy
was built to eliminate.

## Root cause

The autopsy's command lineage clusters *all* bash/eval commands by repetition,
so out-of-repo mutations are invisible unless they happen to repeat, and even
then they are indistinguishable from read-only iteration. No axis of the
report distinguishes "read the user's Mail accounts" from "moved the user's
mail" — the single distinction that matters for post-hoc damage assessment.

## Targeted fix

Extend `SessionAutopsy` with `mutations: { cluster: string; count: number }[]`
— a display-only, lexically classified inventory of commands that plausibly
mutated user data outside the repo. Heuristic classes (documented in tsdoc as
"heuristic inventory for post-hoc audit, not a safety boundary"):

1. osascript invocations whose body contains mutation verbs
   (`move`, `delete`, `make new`, `set `, `save`, `empty trash`;
   case-insensitive, word-boundary);
2. browser-automation invocations (`ego-browser`, or `tab.click` /
   `tab.fill` / `dispatchMouseEvent` in the body);
3. filesystem destruction outside the repo: `rm`/`rmdir`/`mv` with an
   absolute (`/…`) or home (`~…`) target — cwd-relative targets are repo
   work and excluded;
4. sqlite writes to absolute paths (`sqlite3 /…` with
   insert/update/delete/drop in the body).

Cluster key = first line ≤80 chars (same as errors/lineage), count per
cluster, `TOP_LIMIT` rows. Rendered as a new
`out-of-repo mutations (heuristic inventory):` section between lineage and
ending, `  (none detected)` when empty. No severities, no blocking, no
ledger writes.
