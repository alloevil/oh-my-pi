# 2026-08-02-ending-verification

- **Component-class**: observability
- **Date**: 2026-08-02
- **Fix**: `packages/coding-agent/src/health/autopsy.ts` (ending verification fields + render), tests

## Failure evidence

H1 review (user-confirmed): correctness has no sensor — an agent that edits
files and declares success without running anything afterward leaves zero
mechanical trace. Corpus probe (4 real sessions ≥30 turns with mutations):
3 ended verified (execution after the last edit), 1 carried an unverified
tail — demonstrating both that the signal is computable with zero NLP and
that it discriminates on real data. The mail incident separately showed the
"never exercised" shape: work products the session never touched again.

## Root cause

The harness cannot judge output correctness, but it never even asks the
cheaper question it CAN answer deterministically: did verification *happen*?
"Last mutation followed by any execution" and "edited file later referenced
by any executed command" are both computable from the transcript; neither is
surfaced anywhere.

## Targeted fix

`buildAutopsy` ending section gains:

- `lastMutationTurn` / `lastExecutionTurn` (assistant-turn ordinals; mutation
  = edit/write tool calls, execution = bash/eval);
- `unverifiedTail`: last mutation strictly after last execution;
- `mutatedFilesNeverExercised`: files edited/written whose basename never
  appears in any LATER bash/eval command text (cap 5) — a lexical
  containment heuristic, documented as such (a test runner invoked without
  naming the file will false-positive; report-only, human judges).

Render: `verification:` line in the ending section — `✓ execution followed
the last mutation` / `⚠ unverified tail: …` / `no repo mutations`; plus the
never-exercised list when non-empty. In-flight sessions naturally carry
unverified tails; the existing in-flight marker sits adjacent, and the tsdoc
says post-hoc reads only.
