# 2026-08-02-discovery-stack-hardening

- **Component-class**: observability
- **Date**: 2026-08-02
- **Fix**: `packages/coding-agent/src/health/doctor.ts` (`telemetry-liveness` rule), `src/health/subagents.ts` (`sweepSubagentWarns`), `src/session/agent-session.ts` (sentinel child sweep), tests

## Failure evidence

Red-team review of the discovery stack itself (user-confirmed) found two
holes that are cheap to close:

- **H2 — dead instruments read as healthy.** If an upstream merge silently
  breaks the `stage_timings` or `outbound_summary` writers, every gauge reads
  zero and doctor's interpretation of zero rows is "session predates
  tracking" — silent pass. "Instrument dead" and "patient healthy" are
  currently indistinguishable. This has already nearly happened once: the
  ttfb rules were built against rows whose writer shipped days earlier;
  nothing would have flagged their disappearance.
- **H7 (half) — subagent warns don't reach the parent.** The week's big dev
  session spawned 22 children, 8 of which carry warn findings; the parent
  ledger showed `✓` throughout. `--subagents` exposes this only when a human
  asks, post-hoc.

## Root cause

- Telemetry rows are evidence when present but their *absence* is never
  evaluated against expectation (session is recent, long, and the writers
  ship enabled by default).
- The session-end sentinel folds the doctor sweep over the parent's own
  entries only; child transcripts, though discoverable by convention, are
  outside its sweep.

## Targeted fix

1. `telemetry-liveness` doctor rule (warn): fires when the session header
   timestamp is after the fork's telemetry ship date (2026-07-28), the
   session has ≥10 assistant turns, and stage rows (or outbound rows) are
   zero. Message names both possibilities — writer broken or setting
   disabled — because the transcript cannot distinguish them; users who
   deliberately disabled the writers will see one finding saying they are
   flying blind, which is the truthful report of that choice.
2. `sweepSubagentWarns(entries, sessionFile)` in subagents.ts: resolves the
   session's children by the existing directory convention, sums their warn
   findings, and returns one info finding (`subagent-health`) naming
   warns/children with a pointer to `--subagents`; capped at 32 children,
   errors degrade to undefined. Session-end sentinel calls it (try/catch,
   after the doctor fold) so the parent ledger carries the children's state
   by session end.
