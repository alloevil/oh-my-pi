## Failure evidence

The 380-session corpus (2026-07-28 candidate-measurement sweep, see
`incidents.md` #1) contains **zero** outcome labels: no entry type in the
session JSONL records whether the task was actually completed. Every health
detector built so far — error-diversity, dominant-prefix, ttfb-health,
autopsy axes — has independent variables only; there is no dependent
variable to correlate a candidate rule against, so precision/recall of any
proposed detector is unmeasurable (the 2026-07-28 sweep had to hand-judge
"legitimate dev session" vs "flailing" from transcripts). Incident #1's
ground truth — task abandoned to manual takeover, the user organized the
mail by hand — exists only as prose relayed by the user and recorded in
`incidents.md`; the session file `019fac75` itself carries no trace of it.

## Root cause

Sessions record everything the harness did and nothing about whether it
worked. Outcome is post-hoc human knowledge, and there is no write path for
it: the only custom-entry appenders run inside a live `AgentSession`, so
knowledge arriving after the session ends (which is when outcomes become
known) has nowhere to land. Detector development is stuck at "plausible
threshold" because ground truth was never persisted next to the evidence.

## Targeted fix

`omp label <outcome> [session] [--note "..."]` appends a `session_outcome`
custom entry (`{outcome, note?, at}`) to the target session file — resolved
exactly like doctor's target (path, id prefix, or most recent for cwd) and
appended via `SessionManager.open` → `appendCustomEntry` → close, the same
persistence mechanism the session-end sentinel uses (no hand-rolled JSONL).
Outcome vocabulary: `done | partial | manual-takeover | abandoned`. Multiple
labels: **last one wins** — relabeling is a correction, the JSONL stays
append-only. Readers: `parseSessionOutcome` (defensive, same style as
`parseStageTimingsRow`), `scanSession` carries `scan.outcome`, doctor shows
`outcome: <label> — <note>` in the header block (and in `--json`), and the
evidence report's L1 overview gains an outcomes-count line when any analyzed
session is labeled (unlabeled corpora render byte-identically). No automatic
end-of-session prompting, no stats.db schema, no autopsy changes.
